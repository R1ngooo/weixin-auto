# 视频号助手自动化上传工具

自动化执行「视频号助手」的上传/发表流程，并把流程所需的模块化资源按**标签**分组管理：
主体登录信息、视频池、文本池、发表动态页面配置，以及执行结果同步到微信。

> 仅用于管理**自己拥有/有权运营**的视频号账号。请遵守《微信视频号运营规范》，控制发布频率，避免批量刷屏。

## 1. 功能一览

| 模块 | 能力 |
| --- | --- |
| 主体管理 | 微信扫码登录（**默认无头后台运行，不弹出浏览器窗口**；二维码快速捕获/自动刷新，弹窗提供「浏览器扫码」兜底可显示浏览器与原登录页）；每个主体独立浏览器目录保存登录态；卡片**以视频号名称为主显示**（状态徽标统一右上角、与头像/名称同排）；**同一视频号名称/ID 唯一**，重复登录自动合并（保留在线且最近登录的一份，另一份数据与 profile 目录备份）；删除主体后卡片立即消失、历史记录保留、登录态目录备份到 `data/profiles/_deleted`；支持标签分组与筛选 |
| 视频池 | 添加本地视频文件夹并扫描入库（递归/扩展名过滤）；**三种显示模式：卡片（封面竖卡）/ 列表（纯文字信息）/ 文件夹（按本地路径分组，可折叠）**，模式记忆在浏览器本地；卡片面积约为早期版本的 1/3（更紧凑，一屏更多）；系统文件夹选择框（TopMost 置前，另有面板内文件夹浏览兜底）；可为每个文件夹预设**导入标签**，扫描时自动给视频打上；扫描时自动计算 MD5（按 MD5 关联历史记录、改名/移动后仍保留数据）并自动生成封面；**点击卡片/列表行直接预览播放**，鼠标悬浮时**整张卡片播放（隐藏信息等元素，底部可拖动进度条；批量模式下不触发）**，空格全屏快速预览（QuickLook 风格）；分页默认 **20 条/页**，可切换 40/60/80/100/120；已上传视频右上角显示绿色斜绑带「已上传」；卡片上不再有单个「标签/移除」按钮，**打标签与移除统一在「批量编辑」中处理**；**移除视频为软移除**（保留数据库记录与历史数据，重新扫描按 MD5 自动恢复，可选同时删除本地文件）；选择策略：顺序 / 随机可重复 / 随机不可重复 |
| 文本池 | 单条新增或批量导入（每行一条 / 空行分隔 / JSON 数组）；内容全局唯一去重；标签分组；「已使用」标记；用于「视频描述」 |
| 发布页面配置 | 把「主体 + 视频池 + 文本池 + 发表动态页面选项」封装成可重复执行的配置；**资源默认围绕标签组筛选**（同一组资源标签同时筛选主体/视频/文本，也可切换到「指定主体」）；选择策略为「随机（可重复）/ 随机（不重复）/ 固定指定」，**已取消顺序策略**；固定视频/文本支持多选，候选范围 = 资源标签 + 使用状态过滤的交集，任务按顺序循环分配；可设置**每个主体发表数量（1-5，默认 1）**；页面选项含**「先传输完素材，再逐一搭建」**（每条视频先上传→删除循环一遍，再重新上传并搭建，利用秒传缓存减少重复人脸认证）、视频描述（前后缀、附加话题）、短标题（必填 6-16 字）、位置、合集、链接（商品链接或商品ID，执行时自动完成「链接→商品→选择需要添加的商品→按商品ID搜索→选中→添加」）、**定时发表（起点 + 间隔分钟 + 按主体/整个任务作用范围）**、视频标注（置于选项最后）；配置卡片支持**复制全部配置**；选择进度默认不自动重置，已移除手动「重置选择进度」 |
| 执行 | 串行执行任务（避免同一浏览器并发）；每个主体可按配置/任务弹窗设置发表 1-5 个视频（默认 1，单主体上限 5）；每步日志、进度、成功截图/失败截图；支持演练模式（只填写不提交）、保存草稿、直接发表；失败原因与页面截图留档；**演练模式不消耗素材、不改变已上传/已使用状态、不计入使用次数** |
| 页面探测 | 主体卡片上的「页面探测」：快速探测（检查页面就绪、表单字段、选择器命中）与深度探测（自动上传内置测试视频，验证「上传检测 → 视频描述输入框 → 描述写入」完整链路，不保存不发表） |
| 结果同步 | 执行记录页顶部内置微信机器人扫码配置：可导入本机 `dsh-im` 插件已绑定的微信机器人（复用凭据与会话上下文），也可扫码绑定新机器人；任务结束后把执行结果推送到微信 |
| 标签 | 独立「标签管理」页面：**上方标签组区域 + 下方标签列表区域**（各区域右上角有新增按钮）。**标签组**用于分类具体标签（类似「产品」与具体产品名称），每个具体标签归属一个标签组，标签组可设置组内**单选/多选**约束（单选组内任意位置只能选择一个标签），单选约束对全项目生效（筛选、批量打标签、发布配置选标签等）；删除标签组前必须清空组内标签，删除标签前必须解除主体/视频/文本关联；主体/视频/文本均支持**批量选择后一键追加、覆盖或移除标签**；各资源页面的标签筛选为**独占一行的水平标签条**（按标签组分组展示，不与搜索框等混排）；**搜索框可搜索标签名** |
| 配置迁移 | 一键导出设置/标签/主体信息/视频元数据/文本/发布配置为 JSON；新机器导入即可复用 |
| 界面 | 浅色系紫罗兰+珊瑚渐变主题；弹窗只能通过右上角 ×（或弹窗内明确按钮）关闭，点击遮罩不会误取消操作 |
| 系统设置 | **单列瀑布式布局 + 左侧子导航**（点击平滑滚动到对应模块，滚动时自动高亮）；模块顺序：演练测试环境 / 浏览器与运行 / 操作延迟 / 视频扫描 / 选择器（高级）/ 配置导入导出 / 关于；最上方「**演练测试环境**」开关：开启后演练任务也会正常计入视频/文本的使用状态与使用次数（默认关闭，不污染数据），便于验证前端显示效果 |

> 左侧导航顺序（由上至下）：**概览 → 标签管理 → 主体管理 → 视频池 → 文本池 → 发布页面配置 → 执行记录 → 系统设置**。标签管理前移为主体/素材的公共分类层，系统设置承载全局运行参数。

## 2. 快速开始

### 环境要求

- Windows 10/11 x64（当前主要在 Windows 下验证）
- **便携版**：无需安装 Node.js，解压 ZIP 后双击 `start.cmd`（内置 Node 与 Playwright Chromium）
- **源码运行**：Node.js **22.16+**（使用内置 `node:sqlite`，无需编译原生依赖）
- 能访问 `channels.weixin.qq.com`、`res.wx.qq.com`、`open.weixin.qq.com`

### 启动

```bat
:: 便携版：下载 GitHub Releases 中的 weixin-auto-<版本>-win-x64.zip，解压后双击
start.cmd

:: 源码/开发方式
npm install
npm start
```

启动后访问：**http://127.0.0.1:3210**（端口被占用时会自动向后顺延，控制台会打印实际地址）。便携版由 `launcher.mjs` 启动：首次启动会自动打开浏览器；补丁应用后进程退出码 75 会自动重启。

### 浏览器内核

- 自动化使用 Playwright 驱动 Chromium，依赖已缓存的 Chromium（本机 `%LOCALAPPDATA%\ms-playwright`）。
- 如果提示「未找到可用的浏览器内核」，任选其一：
  1. `npx playwright install chromium`
  2. 设置 → 浏览器与运行 → 浏览器内核，选择「本机 Chrome / 本机 Edge」
- 默认使用**有头模式**（能看到浏览器窗口），方便观察与人工接管；可在设置中切换无头模式。

## 3. 使用流程

1. **登录主体**：主体管理 → 扫码登录新主体 → 手机微信扫码并确认。
   - 页面出现「使用其他头像、昵称或账号」时会自动点击切换到扫码；
   - 二维码过期会自动刷新，也可手动点「刷新二维码」；
   - 若该微信下绑定多个视频号，会自动选择（优先选择主体已记录的，其次第一个可用视频号）；
   - 扫码确认后自动读取微信昵称/头像、视频号信息并入库，同一账号再次登录会合并覆盖旧记录。
2. **准备视频**：视频池 → 文件夹管理 → 点「选择文件夹…」用系统对话框选目录（也可手动输入路径），可顺手设置「导入标签」→ 添加 → 立即扫描；扫描后自动计算 MD5、生成封面。视频池支持**卡片 / 列表 / 文件夹**三种显示模式（右上角切换），卡片悬停整卡播放、按空格全屏快速预览；已上传的卡片右上角会出现绿色「已上传」绑带。
3. **准备文本**：文本池 → 导入文本（每行一条）→ 打标签。
4. **批量赋予标签（可选）**：在主体管理 / 视频池 / 文本池点击右上角「批量编辑」，勾选多个卡片或行，再点「批量打标签」，可选择追加、覆盖或移除标签。
5. **创建发布配置**：发布页面配置 → 新建 → 先选资源标签（同时筛选主体/视频/文本），选择主体匹配方式、视频/文本策略与每主体数量，再填写页面选项 → 保存。
6. **先演练**：配置卡片 → 创建任务 → 勾选「演练模式」→ 创建后立即执行；到执行记录查看填写结果与截图。
7. **遇到页面问题先探测**：主体管理 → 页面探测 → 深度探测，验证上传、描述框与填写链路；确认通过后再正式执行。
8. **正式发布**：创建任务时选择「保存草稿」或「直接发表」；执行完成后可在视频号助手「视频管理/草稿箱」核对。
9. **结果同步**（可选）：执行记录页顶部 → 微信机器人 → 导入本机 dsh-im 机器人或扫码绑定 → 在发布配置中勾选「执行结果同步到微信机器人」。

### 资源选择与策略说明

- **资源标签统一筛选**：配置里的「资源标签」同时作用于主体、视频、文本；「按标签自动匹配主体」会包含今后新增的同类主体，「指定主体」可手动勾选任意主体；固定视频/文本只能从「资源标签 + 使用状态过滤」的交集范围内勾选。
- **使用状态过滤默认「仅未使用过」**；固定视频/文本为多选，任务按顺序循环分配（单主体每轮最多 5 个视频）。
- **已取消「顺序」策略**，旧配置会自动迁移为「随机（不重复）」。

| 策略 | 行为 |
| --- | --- |
| 随机可重复 | 每次随机挑选，允许重复 |
| 随机不重复 | 在同一范围（整个配置或每个主体）内不重复使用；用尽后是否自动重置由「选择进度」控制，**默认不勾选**（用尽时提示资源不足） |
| 固定指定 | 使用所选的多个固定视频/文本，按顺序循环分配 |

- **每个主体发表数量**：配置编辑器与创建任务弹窗均可设置 1-5 个（默认 1）；单主体时最多 5 项，多主体时每个主体各自按该数量生成任务项。
- 配置卡片提供「复制」，会复制全部配置内容（名称自动加「（副本）」）。

「预览资源分配」只做预览，**不会**消耗选择进度；已移除手动「重置选择进度」按钮。

## 5. 自动化实现说明

- **Shadow DOM / wujie 微前端**：视频号助手已升级为 wujie 微前端，页面内容位于 Shadow DOM 内，`document.body.innerText` 读不到文本。工具内部统一使用「递归遍历 shadowRoot」的方式读取页面文本，并用 Playwright 定位器（可穿透 Shadow DOM）查找元素。
- **登录态**：每个主体一个 Playwright 持久化用户目录（`data/profiles/<主体ID>`），扫码一次后 Cookie 持久保存；「检查会话」会打开视频管理页判断是否被重定向到登录页。
- **登录判定**：扫码确认后，页面会通过 `oauth-callback` 回传 code；工具轮询站点自身的 `auth/auth_data` 接口并在必要时自动调用 `auth/auth_finder_list` + `auth/login_finder` 完成视频号选择，随后读取账号信息。
- **扫码登录默认无头 + 浏览器兜底**：扫码登录弹窗默认在 **无头 Chromium 后台**运行，不弹出浏览器窗口（系统的 `browser.headless` 设置仍只影响发布/检查/探测等自动化）。弹窗下方提供「浏览器扫码」按钮：点击后会关闭无头会话，用同一 profile 目录重新以有头模式打开 `channels.weixin.qq.com/login.html` 原登录页，方便手动操作；若环境无法显示浏览器会自动回退为面板二维码。无头/有头模式切换由 `browser.getPage(subjectId, { headless })` 管理，同一 profile 不会并发打开两个浏览器。
- **二维码快速捕获/刷新**：二维码图片地址在 qrconnect iframe 内轮询（150ms）获取，优先直接请求图片、失败才截图；刷新时先尝试登录主页的刷新按钮，无效则直接重新加载登录页，并等待图片地址变化（不会把旧码当新码返回）。二维码快照会带上 `qrLatencyMs` / `refreshLatencyMs`，前端登录日志直接显示耗时；实测本机首次二维码约 3-4s、手动刷新约 3-4s（受微信/网络影响）。
- **主体唯一性与显示名称**：主体以**视频号名称为主显示**（`displayName = finderNickname || finderUsername || name`），卡片第二行显示微信昵称/视频号ID。唯一性按「视频号ID → 微信身份（uin/wxid） → 视频号名称 → 微信ID」判定：扫码成功时命中已有主体会自动合并登录态/标签/历史；启动时还会自动合并历史重复主体（保留 active 且最近登录的一份），并把被合并行的历史记录、任务引用、发布配置 subjectIds 改指向保留主体，行数据备份到 `data/backups/subjects-merge-<时间>.json`、profile 目录移动到 `data/profiles/_merged/`。合并后建立 `finder_username` / `lower(finder_nickname)` 唯一索引，防止再次出现同名/同 ID 卡片。
- **删除主体**：确认后**先删除数据库记录并立即返回**，卡片通过乐观更新立即消失；浏览器关闭（8s 超时）与登录态目录清理在后台执行，目录移动到 `data/profiles/_deleted/<主体ID>-<时间>` 备份而不是直接丢失。删除时会先取消该主体正在进行的扫码登录；历史执行记录保留。所有确认弹窗统一走 `confirmDialog`（确定才执行、取消/× 不执行）。
- **进入发表动态**：走「视频管理 → 发表视频」的正常入口（直接访问 `/post/create` 有时会被站点重定向回首页），再等待「视频描述」表单项出现视为页面就绪。
- **上传检测**：以「封面预览 / 更换封面」等上传完成后才出现的标记判定完成，并等待「取消上传 / 上传中 / N%」等提示消失且稳定 2 秒后继续，避免上传未完成就去找描述框。
- **视频描述**：编辑器是 `div.input-editor[contenteditable][data-placeholder="添加描述"]`，按「添加描述」占位与 `.input-editor` 定位，键盘输入后读取编辑器内容校验，失败自动重试。
- **短标题**：自动清理页面不接受的特殊字符（如 `-`、`【】` 等，只保留中英文/数字/书名号/引号/冒号/加号/问号/百分号/摄氏度/空格），避免「标题包含特殊字符」导致无法提交。
- **位置**：点击 `.position-display` 展开搜索面板，输入关键词后选择匹配项；当前已显示目标位置时直接跳过。
- **视频标注**：新版发表页已没有「声明原创」开关，改为「视频标注」下拉（无需标注 / 含AI生成内容 / 内容为虚构剧情，仅供娱乐 / 个人观点，仅供参考 / 内容包含营销广告 / 内容为自行拍摄 / 内容为转载）。
- **视频封面与 MD5**：用无头浏览器（优先本机 Edge/Chrome，其次 Playwright Chromium）加载本地视频文件，seek 到前段/中段多个时间点截图并挑选亮度合适的帧，压缩为 JPEG 存到 `data/thumbnails/<视频ID>.jpg`；MD5 由后台流式读取计算。**扫描时对新文件/内容变化的文件直接计算 MD5**（用于按 MD5 关联历史记录），启动与扫描完成后还会自动补算遗留缺失的 MD5、补生成缺失封面，无需手动操作；也可在视频池点「生成封面」手动触发。原视频更新（大小/mtime 变化）后封面会自动失效并重新生成。
- **文件夹管理**：视频文件夹的增删都在「视频池 → 文件夹管理」，支持 Windows 系统文件夹选择框（由后台 PowerShell 弹出）与**面板内文件夹浏览**两种方式；每个文件夹可预设导入标签（`video_folders.tag_ids`），每次扫描完成时会自动把标签应用到该文件夹下的视频（`INSERT OR IGNORE`，不覆盖手动标签）。
- **系统文件夹选择框说明**：后台进程弹出的对话框容易被浏览器盖住，因此使用一个 **TopMost（置前）的隐藏 owner 窗口**承载对话框，并在显示后再次调用 `SetForegroundWindow` 逼近前台；若仍不可见，可用面板内的「浏览本机…」直接浏览磁盘目录并选择。
- **标签组与具体标签（全项目层级）**：标签体系分为「标签组 → 具体标签」两层（类似「产品」→「具体产品名称」）。具体标签通过 `tags.group_id` 归属唯一标签组（旧数据自动迁入「未分组」）；标签组表 `tag_groups` 保存名称/颜色/备注/`selection_mode`（single=单选、multiple=多选）。**单选约束**由前端选择组件（标签筛选条、标签多选组件）与后端 `assign` 校验共同保证：同一单选组内最多一个标签。删除保护：标签组下有任何具体标签则拒绝删除；具体标签在主体/视频/文本任一关联存在时拒绝删除（文件夹导入标签中的引用会在删除时自动清理）。标签组与归属关系随配置导出/导入一起迁移（`tagGroups` + `tags.group_id`）。
- **先传输完素材，再逐一搭建**：发布配置页面选项顶部可勾选该模式。执行时对同一主体的每条计划先做「上传 → 等待完成 → 删除」预热，直到该主体所有计划视频都上传循环一遍，再逐个重新上传（此时通常命中秒传缓存，不必重复加载/认证）并填写发布信息；任务明细的第一条计划日志会带上素材预热进度。
- **链接（商品）自动化**：配置里勾选「链接」并填写商品链接或商品ID后，执行任务时会自动完成：点击「链接」→ 选择「商品」→ 点击「选择需要添加的商品」→ 在商品选择弹窗里用配置中的**商品ID**搜索（自动从纯ID/商品URL路径/URL参数中解析）→ 选中对应商品 → 点击右下角「添加」（按钮会变为「添加(1)」）→ 回到表单确认链接已回填。账号没有商品/橱窗权限时页面不会出现「商品」选项，任务会在告警中提示「链接设置失败」，其余流程继续。支持所有已有商品权限的主体；历史旧版直接填写链接输入框的页面仍保留兜底逻辑。
- **发布配置资源选择与页面选项**：发布配置的「基本配置 → 资源选择」以标签组为入口：一个资源标签同时筛选主体/视频/文本；主体支持「按标签自动匹配」或「指定主体」；视频/文本可选「随机（可重复）」「随机（不重复）」「固定指定」，默认 `requireUploaded=no`（仅未使用过的素材）。固定视频/文本为多选且只能在「资源标签 + 使用状态过滤」的交集内选择（前端列表过滤 + 后端保存校验）；任务按所选顺序循环分配固定资源。页面选项按「视频描述 → 短标题 → 位置 → 添加到合集 → 链接 → 定时发表 → 视频标注」自上而下排列，已移除「声明原创（旧版选项）」与「使用视频文件名」：短标题勾选后必填且限 6-16 字（`PublishConfigService.validateConfig` 前后端双重校验）；定时发表为「不定时/定时」单选，选定时才显示日期框并校验不早于当前时间（分钟粒度）；「扩展链接」改名「链接」，可填商品链接或商品ID。每个主体发表数量默认 1、上限 5（任务弹窗也可临时调整），单主体任务最多 5 项；配置卡片支持一键复制全部内容；手动「重置选择进度」已移除。
- **视频卡片与显示模式**：视频池提供三种显示模式（工具栏右侧切换，选择记忆在浏览器本地）：
  - **卡片模式**：9:16 抖音式竖版封面 + 卡片底部信息栏（文件名/大小/日期/标签），卡片面积约为早期版本的 **1/3**（宽高按 √3 等比缩小），一屏可展示更多素材；
  - **列表模式**：无卡片，表格展示封面缩略图、文件名、大小、MD5、标签、上传次数、更新时间与本地路径，点击行打开预览；
  - **文件夹模式**：按本地文件夹路径分组展示（分组标题显示路径与数量，可点击折叠/展开），组内仍显示封面卡片。
  点击卡片/行直接预览播放；鼠标悬浮卡片约 0.3 秒后视频在整张卡片内静音循环播放，**播放时隐藏信息栏/绑带/勾选框等元素**，底部显示可点击拖动的进度条与时间；悬浮时按空格打开 QuickLook 风格全屏预览；已上传视频右上角渲染绿色斜向「已上传」绑带（上传多次显示 ×N），文件丢失显示红色绑带。卡片上不再有「预览/标签/移除」按钮：预览点击卡片、打标签与移除都在「批量编辑」批量操作条中完成（列表模式下也可勾选批量操作）。
- **视频封面生成（HEVC 排查修复）**：部分新素材为 **HEVC/H.265 (`hev1`)** 编码，本机 Edge/Chrome 缺少 HEVC 解码器时 `videoWidth=0`，导致封面全部失败。修复为**优先使用 Playwright 内置 Chromium**（自带 HEVC 软解）生成封面，失败再回退本机 Chrome/Edge；同时增加“视频容器快速校验”，非视频/损坏文件快速失败，避免浏览器加载超时。实测 19 个 HEVC 视频全部成功生成封面（25/25 ready）。失败时任务会返回具体原因列表。
- **批量移除**：批量选中视频后点「移除所选」，弹窗默认**不勾选删除本地文件**；移除为软移除，数据库记录与历史数据保留，重新扫描按 MD5 恢复。
- **视频分页**：默认每页 20 条，可切换 40/60/80/100/120 条每页，翻页与筛选/搜索联动。
- **移除视频（软移除 + MD5 关联）**：移除操作**不会删除数据库记录**，仅把视频从视频池列表隐藏；标签、上传历史、使用次数等数据全部保留。重新扫描入库时按 **MD5**（主键）匹配历史记录并恢复（视频改名/移动后同样适用，文件名仅作展示参考）。移除确认弹窗可勾选「同时删除本地视频文件」（默认不勾选）；勾选后会删除本地文件，记录仍保留在数据库中，重新放入同名/同内容视频再次扫描可恢复。设计原因：避免误删历史统计与配置引用，同时保持视频池列表干净。
- **标签筛选条与搜索**：主体/视频/文本页面顶部都有独占一行的水平标签筛选条（可横向滚动，不与搜索/下拉等混排）；搜索框同时匹配标签名（后端 SQL 通过 `EXISTS` 关联标签表实现）。
- **演练模式零污染**：创建演练任务时用 `peek` 只读方式选素材（不写 `pool_usage`/`pool_cursor`），执行时不写 `upload_history`，因此「已上传/已使用」标记与使用次数统计都不受影响。
- **定时发表 / 定时执行**：发布配置的「定时发表」支持起点 + 间隔（分钟）+ 作用范围（按每个主体分别递增 / 整个任务连续递增）；第 N 条计划时间 = 起点 + 间隔 ×（N-1）。起点必须晚于当前时间至少 10 分钟（容错），任务创建时若发现计划时间已过会直接拒绝。创建任务时还可选择「定时执行」（任务级本地定时，默认「创建后立即开始执行」）：到达起点后任务自动开始，各计划按间隔依次执行；**配置已启用定时发表时任务级定时执行会显示但灰置，并提示原因**，前后端都会拒绝同时设置。任务列表/详情会展示定时起点、间隔以及每条计划的计划时间。旧版「尽力选择指定时间」逻辑保留为兼容。
- **操作延迟**：所有步骤之间有可配置延迟（默认 1.2s，输入延迟 30ms，上传后等待 2.5s），以兼容网络波动。
- **页面探测**：主体管理卡片上的「页面探测」提供两种方式：
  - 快速探测：只打开发表动态页，输出是否就绪、表单字段、按钮文案、选择器命中与截图；
  - 深度探测：自动上传 `data/test-media/probe-test.mp4`（约 2.5MB，可替换为任意本地小视频），验证上传检测、描述框识别与描述写入，不会保存草稿或发表，结果附截图与采样日志。
- **选择器失效兜底**：站点改版时可使用「页面探测」查看当前页面结构，再到「系统设置 → 选择器（高级）」用 JSON 深度覆盖默认选择器，例如：
  ```json
  { "publish": { "publishButtonTexts": ["发表", "发 表"], "descEditorSelectors": [".form-item .input-editor"] } }
  ```

## 6. 微信结果同步

- 入口位置：**执行记录页顶部**的「微信机器人（执行结果同步）」面板（与任务结果同屏，便于对照）。
- **导入 dsh-im 机器人（推荐）**：读取本机 `~/.dsh/integrations/dsh-weixin/config.json`、`~/.dsh/.credentials.yaml`、机器人 `state.json` 中的凭据与会话上下文（context_token），导入后可直接向你的微信推送消息。
- **扫码绑定新机器人**：使用微信 iLink 机器人接口申请二维码（`ilink/bot/get_bot_qrcode`），工具把返回的 liteapp 二维码页面用无头浏览器截图后展示；扫码确认后保存 bot 凭据。
- **主动推送**：`ilink/bot/sendmessage`；若缺少 context_token，请先在微信里给机器人发一条消息，再在执行记录页点「刷新连接上下文」。
- **稳定性与续期通知**：发送失败会分类为网络/配置/授权/会话问题；确认是会话（context_token）需要续期时，会先尝试给机器人发微信提醒，失败再弹 Windows 通知并在执行记录页顶部显示「会话需要续期」横幅；同一机器人 10 分钟内不重复通知。重新导入机器人、扫码绑定或刷新上下文成功后会清除待续期状态。
- **稳定性自检**：`npm run test:wechat`（默认 mock，不发送真实消息）；真实发送需 `node scripts/wechat-stability.mjs --live --yes`。
- 任务是否推送由发布配置中的「执行结果同步到微信机器人」与执行记录页的「启用结果同步」共同决定。

## 7. 配置导出 / 导入

- 系统设置 → 配置导入/导出：勾选要导出的内容，导出 JSON 文件（或保存到 `data/backups/`）。
- 新机器导入时选择「合并」（按名称/内容/路径去重）或「替换」（清空标签/配置后导入）。
- 说明：**浏览器登录态（profiles）不会导出**，迁移到新机器后需要重新扫码登录主体；**视频/视频文件夹会导出本地绝对路径**（不复制视频文件）。导入时逐条检查目标机器路径：不存在的视频/文件夹会跳过，并在导入结果弹窗中列出缺失路径，其余数据正常导入；保持原路径或重新扫描即可恢复。
- 更详细的迁移步骤：先在新机器安装/解压便携包 → 导入 JSON → 视频路径不一致时按提示恢复目录 → 重新扫描 → 主体重新扫码登录。

## 8. 数据与隐私

- 所有数据保存在本机 `data/` 目录；服务默认只监听 `127.0.0.1`，不对外网开放。
- 登录态保存在本地浏览器目录；微信机器人 token 保存在本地 SQLite。
- 便携包只包含程序运行文件（Node/Chromium/源码），不包含 `data/`、登录态、token、日志和视频文件；补丁包同样不会修改 `data/`。
- 请勿把 `data/`、`.credentials` 相关内容提交到代码仓库或分享给他人。

## 10. 常见问题

**Q：提示登录态已过期？**
在主体管理点击「重新扫码」，扫码确认后会自动覆盖旧会话。

**Q：执行时提示「未找到按钮/输入框」或「上传后未出现视频描述输入框」？**
站点可能改版。先在主体管理中做一次「页面探测 → 深度探测」，它会实际上传测试视频并输出上传检测、描述框识别、描述写入的结果与截图；若仍然失败，可在「选择器（高级）」覆盖对应选择器，或把探测结果的截图/JSON 反馈给开发者更新默认值。

**Q：深度探测提示测试视频不存在？**
深度探测默认使用 `data/test-media/probe-test.mp4`。可以放任意一个小体积 mp4 到该路径（保持文件名），或调用接口时通过 `uploadFile` 指定其它视频路径。

**Q：视频卡片没有封面 / 显示「暂无封面」？**
封面由无头浏览器解码视频后截图生成。若所有视频都没有封面，通常是本机 Edge/Chrome 不可用或视频编码不被支持；可到「系统设置 → 浏览器内核」确认，或在视频池点「生成封面」重试（后台任务，进度见任务弹窗）。生成失败的视频不影响上传/发布，仅缺卡片封面。

**Q：悬浮卡片没有播放预览？**
鼠标停到卡片任意位置约 0.3 秒即整卡播放；浏览器需支持该视频编码（H.264 在 Chrome/Edge 正常）；若视频文件已丢失（卡片红色「文件丢失」绑带）不会预览。

**Q：点「选择文件夹…」没有弹出系统选择框？**
对话框由后台进程弹出，若被浏览器等窗口遮挡会造成“没有弹出”的错觉；现已用置顶 owner 窗口并强制置前修复。如果仍看不到，请用同排的「浏览本机…」按钮，直接在面板里浏览磁盘和目录选择文件夹（效果一致）。

**Q：从视频池移除视频后，为什么数据库里还能看到？**
这是刻意设计：移除只把视频从列表隐藏（`videos.removed=1`），不会删除数据库记录；标签、上传历史、使用次数都保留。重新扫描该文件会按 MD5 自动恢复原记录（改名/移动也适用）。如需彻底删除本地文件，在移除弹窗勾选「同时删除本地视频文件」。

**Q：视频 MD5 还要手动点吗？**
不需要。扫描时会直接为新视频/内容变化的视频计算 MD5，缺失 MD5 的记录也会自动补算；卡片上不再提供单个 MD5 按钮，重新扫描是唯一的 MD5 关联入口。

**Q：演练模式会不会消耗素材 / 影响统计？**
不会。演练任务用只读方式选素材，不推进选择进度、不写上传历史，视频/文本的「已上传/已使用」标记与使用次数都不会变化。

**Q：有些视频能生成封面，但悬停预览/点击预览没有画面？**
这些素材可能是 **HEVC/H.265** 编码，浏览器端预览依赖本机 HEVC 解码器（Windows 需安装 HEVC 视频扩展）；封面由服务端 Chromium 生成所以不受影响。若需要，可后续增加“服务端转码 H.264 预览片”的能力。

**Q：标签组和具体标签是什么关系？为什么有的标签组只能选一个标签？**
标签组是具体标签的分类（类似「产品」→「具体产品名称」），每个具体标签归属一个标签组。标签组可设置「单选/多选」：**单选组内任意位置只能选择一个标签**（筛选条、批量打标签、主体/视频/文本编辑、发布配置选标签时都生效）；多选组无限制。删除标签组前需先清空组内标签；删除标签前需先解除主体/视频/文本关联。

**Q：扫码登录为什么没有弹出浏览器窗口？**
这是新版默认行为：扫码登录在**无头浏览器**中后台运行，二维码直接显示在弹窗里，不干扰桌面。如果需要在浏览器里手动操作（例如处理验证码/手动选择账号），点击弹窗下方「浏览器扫码」，工具会关闭无头会话、用同一登录态目录重新打开有头浏览器并加载原登录页面；面板二维码仍可继续使用。

**Q：二维码过期后刷新很慢/一直过期怎么办？**
新版刷新逻辑会优先点登录页的刷新按钮，无效则直接重新加载登录页并等待二维码图片地址变化，避免反复取回旧码。实测首次二维码约 3-4s、手动刷新约 3-4s；登录日志里会显示「二维码 xxx ms / 刷新 xxx ms」。若网络访问微信较慢，可在弹窗内重试或改用「浏览器扫码」手动登录。

**Q：为什么两个同名主体的卡片被合并成一个？**
主体以视频号名称作为业务唯一标识：同一「视频号名称/视频号ID/微信身份」重复扫码时不会再新增卡片，而是合并到已有主体。启动时也会自动清理历史重复数据，保留在线且最近登录的一份，并把它名下的标签、上传历史、任务/发布配置引用统一合并；被合并行的数据备份在 `data/backups/subjects-merge-<时间>.json`，profile 目录备份在 `data/profiles/_merged/`。若确实是不同视频号但名称相同，该策略会以保留的一份为准（可在备份中找回旧数据）。

**Q：删除主体后登录态去哪了？还能恢复吗？**
删除主体会立即删除数据库记录（历史执行记录保留），浏览器登录态目录会在后台移动到 `data/profiles/_deleted/<主体ID>-<时间>` 备份，而不是直接销毁。恢复时可把该目录改回 `data/profiles/<新主体ID>`（主体 ID 会变化，需要重新扫码或手动迁移）；注意 profile 目录包含登录 Cookie，请妥善保管。

**Q：系统设置里的「演练测试环境」是什么？**
开启后，勾选「演练模式」创建/执行任务时会正常消耗视频、文本的使用状态并累计使用次数，方便验证「已上传 / 已使用」等前端显示；关闭时演练模式不改变任何使用数据（默认）。修改后需点击右上角「保存设置」。

**Q：上传一直超时？**
大文件上传较慢，可在设置中把「视频上传超时」调到 15-30 分钟，并确认网络稳定；页面显示「网络出错，请重新上传」时会自动判定失败并截图。

**Q：短标题有什么要求？**
勾选「填写短标题」后为**必填**，且长度必须为 **6-16 个字**（前端保存时立即提示，后端也会校验）；已移除「使用视频文件名」选项，短标题只使用输入框中的自定义内容。页面不接受的特殊字符（如 `-`、`【】`，逗号替换为空格）仍会自动清理。

**Q：配置里的「链接」「定时发表」怎么填？**
「链接」可填商品链接或商品ID（原「扩展链接」改名）；执行任务时会自动点击「链接 → 商品 → 选择需要添加的商品」，用填写的**商品ID**搜索、选中并点右下角「添加」。填整条商品链接时会自动解析其中的商品ID。该功能要求登录主体有商品/橱窗权限：页面没有「商品」选项时任务会在告警中提示「链接设置失败」，其余步骤继续。「定时发表」选「定时」后填写**起点 + 间隔（分钟）+ 作用范围**：起点需晚于当前时间至少 10 分钟（容错），第 N 条计划时间 = 起点 + 间隔 ×（N-1）。创建任务时也可选任务级「定时执行」，但配置已启用定时发表时该项会灰置不可选。

**Q：勾选「先传输完素材，再逐一搭建」有什么用？**
勾选后会先对每个计划视频执行「上传→删除」预热循环，全部素材都上传一遍后，再逐个重新上传并搭建发布信息。这样第二次上传通常命中秒传缓存，可减少短时间重复加载/触发人脸认证等繁琐操作。

**Q：为什么配置里的「声明原创」不见了？**
新版发表页已没有「声明原创」开关，改为「视频标注」下拉；该旧选项已从配置中移除，请直接使用最后一项「设置视频标注」并选择对应选项（无需标注时不会中断任务）。

**Q：为什么浏览器窗口一个接一个弹出？**
默认串行执行，每个主体使用独立浏览器；可在设置里开启无头模式，或调低「浏览器空闲自动关闭」时间。

**Q：微信推送失败？**
先在执行记录页顶部的微信面板点「发送测试消息」；若提示缺少上下文，先在微信中给机器人发一条消息后再点「刷新连接上下文」。导入自 dsh-im 的机器人默认带上下文。

## 12. 便携版、打包与补丁升级

### 便携版

- GitHub Releases: <https://github.com/R1ngooo/weixin-auto/releases>
- 下载 `weixin-auto-<版本>-win-x64.zip` → 解压到任意目录 → 双击 `start.cmd`（无需安装 Node；包内 `runtime/node.exe` 与 `runtime/ms-playwright` 已内置）。
- 首次启动会自动打开面板；数据保存在解压目录旁的 `data/`，升级补丁不会修改该目录。
- 如需更新浏览器内核，使用完整包升级（补丁只包含源码/页面文件）。

### 补丁包升级

- 应用内：「系统设置 → 关于 → 软件升级」选择补丁 `.zip`，确认后自动校验/备份/更新；便携版会通过 launcher 自动重启，开发模式需手动重启。
- 补丁从 GitHub Releases 获取，命名 `weixin-auto-patch-<from>-to-<to>.zip`；请只使用官方 Release 的补丁。
- 补丁内容限制在 `server/`、`web/`、`version.json`、`start.cmd`、`launcher.mjs`、README 等程序文件；`data/`、登录态、视频路径、`node_modules/`、Chromium 不会被补丁修改。依赖/运行时变化必须发布完整包。
- 应用前会备份被覆盖文件到 `data/backups/updates/`，更新历史见 `data/updates/history.json`。

### 本地构建命令

```bash
npm install
npm run build:portable                  # 生成 dist/weixin-auto-<版本>-win-x64.zip + sha256
npm run test:package                    # 验证 staging 便携包（Node/Chromium/health/升级接口）
node scripts/build-patch.mjs --from <ref> --to <ref>    # 生成补丁 zip（需先修改版本号）
npm run test:patch                      # 补丁应用/校验/回滚自检
```

- 构建便携包需要本机有 Playwright Chromium 缓存（`npx playwright install chromium`）与 Node 22.16+。
- `.github/workflows/release.yml`：推送 `v*` tag 时在 GitHub Actions 自动构建便携包、补丁（有上一个 tag 时）并上传 GitHub Releases。

## 13. Git 版本管理与开源仓库

- 仓库：<https://github.com/R1ngooo/weixin-auto>（公开）
- 分支：`main`；发布标签：`v<版本>`（如 `v0.2.0`）。
- **不会入库**：`data/`（数据库、登录态、截图、封面、备份等含隐私/运行数据）、`node_modules/`、`dist/`、`runtime/`、测试隔离目录（`.smoke-data/`、`.ui-data/` 等）、日志与临时文件，详见 [.gitignore](.gitignore)。
- 迁移代码时直接 `git clone` 后 `npm install` 即可；运行数据请通过「系统设置 → 配置导入/导出」迁移。
- 发布新版本：同步修改 `package.json`/`version.json` → 运行测试 → 构建便携包/补丁 → `git commit` → `git tag vX.Y.Z` → 推送 `main` 与 tag。
